# 萌虎 CMS 部署教程（小白版）

> **目标**：跟着点鼠标，把博客后台部署上线。**不用终端、不用敲命令，手机浏览器也能完成**（电脑更舒服）。
> **部署完之后**：打开 `你的域名/admin/` → 登录 → 写文章 → 点发布 → 1 分钟后自动上线，没有别的步骤。
> 已经部署过、只是来查问题的，直接拉到「常见问题」。

## 开始前

- 📱 手机可以完成全部操作；有电脑更舒服一点（两个网站来回切换方便）
- 你的博客仓库是 GitHub 上的 `qilingzon/Meotiger-Blog`（不用管它，教程会带你去连）

---

## 第 1 步：先把网站部署上线（不需要任何配置，约 5 分钟）

> 妙处在这里：**第一次部署一个变量都不用填**，先让网站活起来，配置稍后在网页上点几下就行。

1. 浏览器打开 **https://console.cloud.tencent.com/edgeone/pages**
   - 没有腾讯云账号？微信扫码登录即可
2. 点 **「创建项目」** → 选 **「从 Git 仓库导入」**（第一次会让你授权 GitHub，点同意授权）
3. 选中仓库 `Meotiger-Blog`，按下表填写（**其余保持默认**）：

   | 项目 | 填什么 |
   |---|---|
   | 构建命令 | `npm run build` |
   | 输出目录 | `dist` |
   | 生产分支 | `master` |

4. 什么都不加，直接点 **「部署」**，等 1–3 分钟。

> ✅ **到这里你应该看到**：部署列表里出现绿色的「部署成功」，页面会给你一个 `xxx.edgeone.app` 或自定义域名。

---

## 第 2 步：打开「部署助手」，点几下拿到 4 个变量（约 3 分钟）

1. 浏览器打开 **`http://你的域名/admin/setup.html`**（就是刚上线的网站自带的页面）
2. 在页面上：
   - **① 用户名/密码**：给后台定一个登录账号（密码至少 8 位，记到安全的地方）
   - **② 登录密钥**：页面已自动生成，不用管
   - **③ GitHub 令牌**：点「点我去 GitHub 生成（权限已帮你勾好）」→ 登录 GitHub → 拉到页面最底部点绿色「Generate token」→ 复制那串 `ghp_` 开头的令牌 → 粘贴回助手页面
   - **④** 页面把 4 行整整齐齐列出来，每行一个「复制」按钮，也可以「一键复制全部」

> ✅ **到这里你应该看到**：助手页面显示「✅ 齐了！」，4 行变量每行都有值。
> ⚠️ 里面有密码和令牌：不要发给别人、不要截图外传；配完把助手页面关掉。

---

## 第 3 步：把 4 行粘贴进 EdgeOne（约 2 分钟）

1. 回到 EdgeOne 控制台 → 你的项目 → **设置 → 环境变量**
2. 逐条添加：变量名照抄（如 `CMS_USERNAME`），值从助手页面复制
   - 注意复制时**别带上前后空格**
3. 保存后点 **「重新部署」**，等 1–2 分钟

> ✅ **到这里你应该看到**：部署成功（这一次带上了配置）。

---

## 第 4 步：验收（约 2 分钟）

- [ ] 打开 `你的域名/admin/`，能看到粉色萌虎登录页
- [ ] 用第 2 步设置的用户名密码能登录，欢迎语显示你的用户名
- [ ] 写一篇测试文章点「发布」→ 1 分钟后博客首页能看到它
- [ ] 没问题的话，把这篇测试文章删掉 🗑

**到此部署完成。** 日常写文章只有三个动作：打开后台 → 写 → 点发布。

---

## 怎么写文章：小白写作模式（默认）

打开「写新文章」就是**小白模式**——像搭积木一样写，不用学任何符号：

- 点 **＋ 段落 / ＋ 大标题 / ＋ 列表 / ＋ 任务清单 / ＋ 图片 / ＋ 表格**……想加什么点什么
- 选中文字点 **加粗 / 斜体 / 链接** 等小按钮，效果立刻套上
- 插入图片：点「选图片」从媒体库挑，或者**直接把图片粘贴/拖进图片块**，会自动压缩上传
- 每个块可以 **拖动排序**（按住 ⠿）、上移下移、复制、删除（有确认），写错了 **Ctrl+Z** 撤回
- **30 秒自动暂存**：断电、误关页面，重开后会问你要不要恢复上次内容
- 右上角「专注」隐藏文章信息专心写，「预览」看最终效果

内容底层存的是标准 Markdown，**进阶写作**按钮可切到原来的 Markdown 双栏（给习惯写 Markdown 的人），随时切回，两种模式内容互通。旧文章在小白模式里打开也安全：复杂的语法会显示为「原始 Markdown」块原样保留，不会写坏。

## 写坏了？翻版本（历史回滚）

编辑一篇文章时，顶栏有个「**历史**」按钮：

- 点开就是这篇文章**最近的修改记录**（什么时候改的、提交说明是什么）
- 点任意一条，能先**预览那一版**长什么样
- 觉得那版更好，点「**回到这一版**」，整篇文章（正文、标题、标签）就恢复过去——当前没保存的修改会被它替换（有确认弹窗，不会误碰）

每保存一次就自动留一个版本，所以放心大胆改，随时能反悔。

## 常见问题（按症状查）

| 症状 | 原因与解法 |
|---|---|
| 登录页提示「CMS 尚未配置」 | 还没做第 2–3 步（或加了变量没点「重新部署」）。提示里也写了助手地址，点开照做即可 |
| 令牌验证不过 / 保存文章报权限错误 | 助手页面给的 GitHub 链接已自动勾好权限；如果自己另建的令牌漏勾 `repo`，重新生成一个，回 EdgeOne 只更新 `CMS_GITHUB_TOKEN` 再「重新部署」 |
| 构建失败 | 打开部署日志看报错；最常见是环境变量值里粘了多余空格 |
| 忘记密码 | EdgeOne 环境变量里改 `CMS_PASSWORD` → 点「重新部署」，用新密码登录 |
| 连续输错 5 次被锁 | 等 15 分钟自动解锁；等不及就在 EdgeOne 点「重新部署」立即解锁 |
| 发布后前台没变化 | 正常，构建约 1 分钟，刷新再等一下；后台仪表盘的数字变了就说明保存成功了 |
| 助手页面安全吗 | 它是随网站自带的纯静态页面，**零网络请求、不保存任何内容**，断网也能用；配完建议关闭 |

## 技术参考（一般不用看）

- **组成部分**：`public/admin/` 全中文三主题单页应用（含 `setup.html` 部署助手）+ `edge-functions/api/[[default]].js` 边缘函数（登录鉴权 + GitHub 读写代理）+ `scripts/cms-dev.mjs` 本地环境（8090 端口）。
- **本地配置**：`.env.local`（已被 gitignore）存放 6 个变量：4 个核心变量 + 可选覆盖 `CMS_REPO` / `CMS_BRANCH`。
- **登录机制**：账号密码（环境变量校验，常数时间比较），令牌 HMAC 签名、12 小时有效；连续错 5 次锁 15 分钟（滑动窗口，重新部署即清零，无解锁后门）。
- **安全底线**：GitHub 令牌只存在服务端环境变量里，浏览器接触不到；所有出站请求走白名单，仅放行 `api.github.com`（含 GraphQL 端点）；`/admin/` 带 `noindex`。
- **发布记录**：所有写操作生成中文 commit message（如「CMS: 更新《标题》」），git 历史即审计日志，删除的内容随时可从历史恢复。
- **手动配置**：不想用任何向导，也可以手工准备 4 个值——用户名密码自己定；密钥用 `openssl rand -hex 24` 生成；令牌在 GitHub → Settings → Developer settings → Personal access tokens 创建（勾 `repo`，只授权本仓库）。
